Cat-GDI8 documentation

How the engine control model works and how to set the unit up for your engine in BrainBus GDI-8.

Firmware is in development. The model is verified with automated tests and the ECU simulator; testing on a running engine is the next stage. Each section is marked: Ready works in the simulator, In progress written and waiting for hardware tests, Planned not yet implemented.

One firmware, any engine Ready

Cat-GDI8 is not built for one specific engine. Everything that depends on the engine and its wiring is described as data in BrainBus GDI-8 and stored in the unit. The firmware is the same for every installation.

The control model works with logical values — intake pressure, intake cam position of bank A, the phaser valve of bank A. The configuration decides where each value comes from and which physical pin each output uses. The application shows which pins are suitable for each function and checks the result: one pin — one function.

  • 2 to 8 cylinders, firing order and cylinder angles (even and uneven V8, V6…), bank of each cylinder.
  • Injectors: flow at reference pressure, opening delay from voltage and pressure, minimum pulse.
  • Coils: passive 12 V or with built-in igniter 5 V; dwell from battery voltage.
  • 0–4 camshafts with roles (intake/exhaust, bank A/B), each with its own wheel and phaser.
  • Boost: none, one or two turbos; wastegate pneumatic or electric; 1 or 2 throttles.
  • Knock sensors 0–2, wideband lambda 0–2, propeller drive parameters if known.

Torque-based control In progress

The unit does not convert the throttle lever directly into throttle opening. The lever is a torque request. The model decides how to deliver this torque — with air, with spark timing or, in an emergency only, by cutting cylinders — and all limits act on torque. This is the same principle as in modern OEM engine management, adapted to an airboat: engine, gearbox and a heavy propeller.

Model levels

  1. Position and time — crankshaft and four camshafts give the engine angle and cam phases.
  2. Sensors — every value has a validity flag; a failed sensor is replaced by a model value.
  3. Engine model — cylinder filling, residual gas, spark and mixture efficiency, losses, exhaust temperature.
  4. Torque structure — request, coordination, limits, split into air / spark / cut.
  5. Actuator targets — throttle, cam phases, fuel mass, injection timing and split, rail pressure, spark.
  6. Outputs — angle-based scheduling on hardware timers drives injectors and coils.

At idle the air path keeps a small torque reserve above the target, and spark timing uses it. This lets the idle react instantly, without waiting for the intake manifold to fill. The actual torque is calculated forward the same way and used for supervision and logs.

Air and fuel In progress

Cylinder filling

Air mass is calculated from intake pressure with a linear model: slope and offset depend on rpm and on intake and exhaust cam positions, with a temperature correction. Each bank is calculated separately because each has its own cam phases. The model is easy to invert: from the required air mass the unit gets the required intake pressure and, through the throttle flow model, the throttle angle.

Fuel

Fuel mass per cylinder = air mass / (stoichiometric ratio × target lambda). Target lambda comes from the base map, start and warm-up corrections, component protection enrichment and the wideband correction.

Hybrid injection

For each cylinder the calculated fuel is split between the direct injector and the port injector. Direct injection can use 1–3 pulses per cycle with a high-voltage current profile from the calibration; start of injection depends on rpm and load. Injector open time is calculated from the injector model for the actual pressure difference.

Rail pressure

Two high-pressure pumps, one per bank. Target pressure is a 32×32 map of rpm and load; control combines feed-forward from fuel demand with a rail model and integral action near the target.

Valve timing

Targets for four cams are maps of rpm and load. Control is allowed only with enough oil pressure; on low oil pressure the cams return to the base position. Chain stretch, phaser and end-stop faults are diagnosed.

Rev limiter and propeller protection

In progress An unloaded propeller can over-rev the engine almost instantly, so the limiter works ahead: it looks at acceleration and removes torque smoothly in a band below the limit — first with spark, then with air. In the simulator, a propeller unloading at full power gave a peak of 6426 rpm with a 6500 rpm limit, without cutting a single cylinder. Fuel cut on extreme over-rev is a separate setting and is off by default.

Planned Gearbox and propeller protection: a drive model (engine + gearbox + propeller), torque rate limits, soft passage through zero torque to take up gearbox backlash, damping of torsional oscillations with spark timing, and a keep-out band around the driveline resonance. Until the drive parameters are known, the unit uses a careful mode with slow torque ramps.

Protections and fault reactions In progress

Every fault has a code in OBD format and a reaction from a table that can be edited in the application. Reactions are grouped by level. As a rule, limits reduce torque smoothly instead of cutting fuel or spark.

LevelReactionExamples
R0Fault code onlyKnock sensor noise, wideband sensor
R1Torque limitMAP sensor replaced by model, knock at retard limit, overheating start
R2Limp mode: rpm limit (~2500) and torque limitThrottle or lever partly failed, overheating, low oil pressure
R3Engine stopNo oil pressure, throttle not controlled and open, supervision failure

Injection and spark are timed by hardware timers, never by a data bus. A second processor core independently checks that the actual torque does not exceed what the lever allows. An external watchdog resets the processor if the engine task stops responding; on any reset the outputs are off.

Setup step by step

Setup is done in the BrainBus GDI-8 application for Windows. The application is organised in modules: Engine, Trigger, Sensors, Actuators, Start, Idle, Boost, Ignition, Fuel and mixture, Operation (torque), CAN.

  1. ConnectConnect the unit to the PC with an Ethernet cable and press Connect. The application finds the unit, reads its catalogue of parameters and shows its firmware and serial number. Live data is updated 20 times per second.
  2. Describe the engineIn the Engine module: number of cylinders, firing order, banks, injectors, coils, boost, throttles and camshafts. These choices switch on the modules you need — for example, Boost appears only if a turbo is configured.
  3. Assign inputs and outputsChoose a pin for each function — the application offers only suitable pins and warns about conflicts. Use the pinout to wire the harness. Free outputs can become user outputs: on a condition, PWM from a table, or on a fault.
  4. Set up the triggerDescribe the crank wheel (36-1, 60-2, 36-2-2-2…) and the shape of each camshaft. Record the signals with the built-in trigger logger while cranking and confirm that the wheel and phases are recognised.
  5. Calibrate sensorsChoose sensor types and scales: pressures, temperatures, throttle and lever positions (two channels or SENT), knock sensors, wideband lambda over CAN.
  6. Learn throttles and wastegatesRun end-stop learning and the automatic PID tuning for each electronic throttle and electric wastegate.
  7. Prepare the startCheck cranking fuel, cranking spark and warm-up tables for your engine. The ECU simulator in the application lets you check the calibration before the first start.
  8. Enter the propeller driveEnter gear ratio and allowed gearbox torque if known. Inertia and propeller load can be learned on the engine; until then the careful mode with slow torque ramps is used.
  9. Save and logPress Save to ECU — calibrations are written to the unit's memory with rollback. Run the engine, record logs and refine the maps.

Working with calibrations Ready

  • Maps are 32×32, curves have 16 points. Each value is checked by the unit; a value outside limits is refused.
  • Table axes are shared: change the rpm axis once and every table with this axis is recalculated, keeping the same values at the same rpm. Pressure axes follow the calibration of their sensors.
  • Structural changes — wheels, output assignment, number of cylinders — are applied only with the engine stopped. Calibration values can be changed while the engine runs.
  • A calibration can be saved to and loaded from a file on the PC.
